# 戰情室專案開發守則 (Project Rules)

本專案必須嚴格遵守以下開發守則，且在後續對話與任務執行中，**絕對不能被清洗或簡化**：

1. **不編碼**：當使用者提到『不編碼』時，代表僅針對需求進行討論、架構規劃或方案分析，**絕對不能動手修改任何程式碼或執行寫入操作**。直到使用者明確回覆同意計畫或同意實作，才可以開始動工改動程式碼。
2. **實作前物理備份 (帶時間戳，禁止覆蓋)**：每次修改程式碼前，除了 Git 版控外，必須將該次實作會影響的檔案（特別是 `.py` 檔案）與資料庫（`.db` 檔案），物理備份（複製）一份至專案底下的 `bak\` 目錄中。**備份檔名必須加上精確的時間戳（例如 `Stock_Sentinel_20260723_151500.py`），且絕對不允許對已有的備份進行任何刪除、修改或覆蓋操作**。
3. **備份唯讀性**：`bak\` 目錄底下的任何備份檔案，**只能作為唯讀參考**，任何寫入、修改或工具替換操作，**絕對不能**以 `bak\` 目錄下的檔案作為修改目標。
4. **部署與發布確認**：在實作或修改完成後，主動詢問使用者是否需要部署並發布至 GitHub Pages。不再需要每次程式修改後都封裝成 zip 壓縮檔。
5. **雙重確認實作工作流**：每次實作前必須採用以下雙重防線：
   * **第一次確認**：先撰寫 `implementation_plan.md`，使用者對齊並確認技術方案大方向。
   * **第二次確認**：在動手修改任何原始碼前，必須建立並向使用者展示細部的 `task.md` 任務 TODO 清單。使用者對齊並確認修改細節與清單後，回覆「同意實作」或「開始動工」，才能開始執行物理備份與程式編碼修改。
6. **計畫與任務之實體備份存檔**：當使用者下達「保存 plan task」或類似要求時，必須將當前未完成的 `implementation_plan.md` 與 `task.md` 核心內容，物理複製/寫入備份至 `.agents/NEXT_PLAN.md` 與 `.agents/NEXT_TASK.md` 檔案中，確保下次會話啟動能直接讀取對齊。
